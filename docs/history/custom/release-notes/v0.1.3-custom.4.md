# v0.1.3-custom.4

**基于上游**：Sidenai/sidex main@ad978652（v0.1.3-dev）

## 自定义改动

本轮聚焦 VAC 扩展（vscode-acp-client）在 SideX 里的移植链路修复，三项改动让 VAC 侧边栏完全可用：

- **活动栏图标空白**：`file://` 资源 URL 由自造的 `sidex-asset://localhost/<enc>` 改为 Tauri 官方 asset 协议 `https://asset.localhost/<enc>`（`useHttpsScheme:true`，scope 含 `$HOME/**`）。原 scheme 从 dev origin 发起的请求被 webview 网络层拒绝，图标一直空白。
- **TreeView "no data provider" / "Loading sessions"**：实现扩展 TreeView data provider 跨进程桥——宿主侧 `getTreeChildren` RPC（调扩展 `getChildren` + `TreeItem` 序列化 + handle 反查表）+ 前端代理 `ITreeViewDataProvider`；`onDidChangeTreeData` 经 `treeViewInvalidate` 转发触发 `treeView.refresh()`；并修复 `_getOrCreateTreeView` 未缓存 `existing.treeView` 导致 refresh 通知不命中。VAC 的 Agents 树现在能列出历史 sessions。
- **WebviewView 永久 Loading**：补 `onDidDispose`（VSCode 正确 API 名，此前宿主只提供 `onDispose`），VAC 的 `resolveWebviewView` 调用即抛错导致 `setVisible/refresh/post` 全不执行。Dashboard / Chat 面板现在能正常渲染。
- **补注册 `IAccessibleViewInformationService`**：上游负责注册的 accessibility contribution 未移植，导致 `type:"tree"` 扩展视图构造抛 "depends on UNKNOWN service"。新增纯自定义模块在 ViewPane 创建前注册。
