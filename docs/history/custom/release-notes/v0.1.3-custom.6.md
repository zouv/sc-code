# v0.1.3-custom.6

**基于上游**：Sidenai/sidex main@ad978652（v0.1.3-dev）

## 自定义改动

- **编辑器标签拖拽恢复（关键）**：Windows 下 Tauri 原生拖放接管会吞掉 webview 内**所有** HTML5 拖拽（编辑器标签、资源管理器、视图重排全部拖不动，且无任何报错）。现关闭 `dragDropEnabled`，页内 drag & drop 全部恢复；`.vsix` / `.code-workspace` 等外部拖入改由 HTML5 drop 处理（`CUSTOM-20261017-001`）。
- **扩展热更新修复**：应用运行期间更新扩展（例如 VAC 1.3.0）后，扩展宿主仍跑旧代码，点它新增的菜单会报 `command '…' not found`。现在宿主会检测扩展磁盘代码变化并自动重载、重新注册命令（`CUSTOM-20261017-002`）。
- **扩展对话框修复**：`vscode.window.showOpenDialog` / `showSaveDialog` 的结果此前不会回传到扩展（宿主侧 promise 永不 resolve，120s 后返回 `undefined`），表现为「选了目录/文件但扩展没拿到」。现在按正确形状回传，并把路径还原成 `Uri`（`CUSTOM-20261017-003`）。
- **外部文件拖入**：拖入普通文件可以打开（无路径时是内容副本，且初始**不再**显示未保存标记）；`.code-workspace` 按落点区分——**拖到标签栏 = 当文件打开**，**拖到编辑区 = 打开 workspace**（`CUSTOM-20261017-005` / `CUSTOM-20261017-006`）。
- **多根 workspace 修复**：拖入配置了多个 folders 的 `.code-workspace` 时只打开一个目录的问题已修复（多根与 settings 完整保留，`CUSTOM-20261017-007`）。

## 已知限制（Tauri / WebView2 能力边界）

- Windows 上 WebView2 的 HTML5 拖入**拿不到操作系统的文件路径**（`File.path` 与 `text/uri-list` 均不可用）：普通文件只能以内容副本打开；`.code-workspace` 若 folders 全为绝对路径，会用一份稳定路径的临时副本打开（多根与 settings 保留），含相对路径时需点一次「Locate File…」重新定位原文件。
- 根因：宿主侧同时拿到拖拽数据又放行页内 HTML5 拖拽的 API 只存在于 WebView2 的 composition hosting，而 wry/Tauri 使用 HWND 托管（详见 `CUSTOMIZATIONS/docs/pitfalls.md` #18/#20）。要彻底零交互兼顾，需要改 wry/Tauri 或等待上游支持。
