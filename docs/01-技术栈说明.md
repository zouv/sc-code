# 01 · 技术栈说明

> 面向使用者/维护者：本项目用了哪些技术、为什么这么选、各自负责什么。
> 代码在哪、怎么连，见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 总览

| 用途 | 选型 | 为什么 |
|---|---|---|
| 桌面外壳 | Tauri 2 + Rust | 复用系统 WebView，安装包与内存占用比 Electron 小；Rust 侧承载窗口、运行时与本地服务 |
| 工作台前端 | React + TypeScript + Vite | 组件化 UI、严格类型；Vite 提供快速热更新 |
| 扩展宿主 | Node.js | 兼容 VS Code 扩展 API 的真实运行环境；内置扩展与第三方扩展走同一宿主 |
| Agent / 本地服务 | Go | 独立进程承载 agent、终端与本地能力，便于跨语言隔离与独立测试 |
| 打包 | Tauri CLI（MSI / NSIS）+ WiX | 平台原生安装包；构建脚本统一由 `manager.sh` / `package.bat` 入口 |
| 平台 | Windows 10+ x64 | 当前主要发布平台；Linux / macOS 走 CI 矩阵验证 |

## 各组件职责

- **`src/`**：React 工作台（编辑器区域、侧边栏、状态栏、命令面板）；只通过 IPC / 服务层访问原生能力。
- **`src-tauri/`**：Rust 桌面壳、窗口管理、IPC 命令、运行时资源准备；不承载业务 UI。
- **`agent/`**：Go agent / 本地服务，提供终端、文件与 agent 能力；通过本地协议与桌面通信。
- **`extensions-rust/` / `extensions-meta.json`**：内置扩展与扩展元数据；扩展宿主按真实 Node 环境运行。
- **`manager.sh` / `*.bat`**：构建、测试、打包的统一入口；脚本本身不复制业务逻辑。

## 配置与运行

- 版本号只在 `package.json` / `src-tauri/Cargo.toml` 等工程文件按项目约定维护；发版前用 `manager.sh test` 与 `package.bat` 校验。
- 命令统一走 `sh manager.sh <命令>`；Windows 双击脚本见 README。
- 用户数据与缓存按项目约定隔离，不写程序安装目录。
